# 拾录（ShiLu）产品开发文档

## 1. 产品定义

拾录是一款只支持 Windows 的个人资料收集与内容整理桌面软件。用户把 Telegram、网页、聊天记录或其他来源的截图导入软件，先由 OCR 或视觉模型提取信息，再由用户编辑、补充链接和图片，最后保存为一条独立的 Markdown 资料。

产品的核心承诺是：任何值得保存的内容，都能在几分钟内从截图变成可搜索、可编辑、可迁移、可供 AI 阅读的个人资料。

## 2. MVP 范围

### 必须实现

- Windows 桌面 EXE，支持 Windows 10 及以上 64 位系统。
- 新建资料：拖入或选择一张/多张图片。
- 图片预览、排序、删除和追加。
- OCR 使用单独配置的视觉模型 API，不使用本地 OCR 回退。
- 截图收集、标题/来源补充、正文编辑为同一篇资料的三个连续步骤。
- 文章编辑：标题、正文、来源、链接、标签、个人备注。
- 文案润色使用另一组模型 API，针对最新正文生成结果，用户确认后采用。
- Markdown 编辑与预览支持正文中直接粘贴配图，配图不参与 OCR。
- 新建过程使用内部临时状态保障 OCR 失败重试；用户界面不提供草稿箱。归档箱收纳不常用的正式资料并支持恢复。
- 确认保存为“一条资料一个文件夹”。
- 按标题、正文、标签、来源和链接进行关键词搜索。
- OCR 源截图、原始识别文本、最终文章和正文配图分开保留；源截图默认只在编辑页查看。
- 设置两组模型地址、API Key、名称和开关；按用户确认，Key 普通本地保存，不加密。
- 获取模型列表只需地址与 Key；测试使用当前表单选择，OCR 与润色可同时测试，分别反馈结果。

### 暂不实现

- Telegram 自动登录和历史消息同步。
- 小红书、知乎、抖音等平台的自动发布。
- 云端账号体系和多人协作。
- 依赖数据库才能运行的功能。

## 3. 用户主流程

```text
Step 1 粘贴/选择截图，预览并排序
  -> Step 2 补充标题与来源链接
  -> 点击“下一步：识别并编辑”，先保存临时状态，再调用 OCR
  -> Step 3 OCR 文字直接填入 Markdown 正文
  -> 手动纠错、可选 AI 润色、在光标处粘贴正文配图
  -> 确认保存到资料库
  -> 不常用的资料可归档，需要时恢复

中途切换页面：临时状态用于保护当前流程；完成正文后进入资料库，用户无需管理草稿箱。
OCR 失败：留在信息补充步骤，可重试；保存失败不丢弃当前内容。
```

## 4. 文章字段

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| title | 是 | 资料标题 |
| content | 是 | 用户确认后的正文 |
| summary | 否 | 摘要 |
| source | 否 | 来源平台、频道或作者 |
| links | 否 | 用户补充或模型识别出的链接 |
| tags | 否 | 分类和搜索 |
| notes | 否 | 用户自己的补充 |
| created_at | 是 | 创建时间 |
| updated_at | 是 | 最后修改时间 |
| images | 否 | 与文章关联的图片 |
| ai_meta | 否 | 模型、识别时间和原始结果摘要 |

当前实现以 Markdown front matter 的 `status`（draft/active/archived）、`capture_step`（1/2/3）和 `source_images`（有序相对路径）记录生命周期。无状态字段的旧资料按正式资料读取。所有状态共用 `<资料库>/articles/<文章文件夹>/index.md` 和 `images/`，归档不移动或删除文章文件夹，截图与配图通过用途记录区分。

## 5. 验收标准

- 用户不配置 API Key 也能创建资料、保存图片、编辑 Markdown 和搜索。
- 配置兼容 OpenAI Chat Completions 的 OCR 模型后，多张源截图按顺序生成可编辑正文。
- 识别结果出现错误时，用户可以在保存前修改；原图永远保留。
- 每条资料都能单独复制、备份和用其他 Markdown 工具打开。
- 软件关闭并重新打开后，已保存的资料、搜索结果和设置仍然可用。
- AI 请求失败、超时或 Key 错误时，资料不会丢失，界面给出可理解的错误信息。
- 模型列表无需预填名称；双模型测试互不清除进度，成功展示所测模型和返回文字。
- 配图粘贴在正文光标位置，写入文章 images/ 并使用相对路径，保存重开后可预览。
- 阅读页只渲染 Markdown 正文中实际引用的图片；删除图片引用后不再显示，来源链接位于正文末尾。
- 正式资料和归档列表相互隔离；归档恢复不丢失文字、图片或来源记录。内部临时状态不在导航和列表中展示。
