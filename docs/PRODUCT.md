# 拾录（ShiLu）产品开发文档

## 1. 产品定义

拾录是一款只支持 Windows 的个人资料收集与内容整理桌面软件。用户可以把从 Telegram、网页、聊天记录或其他来源复制来的文字直接整理成资料，也可以粘贴或选择配图，最后保存为一条独立的 Markdown 资料。

产品的核心承诺是：任何值得保存的内容，都能快速变成可搜索、可编辑、可迁移、可供 AI 阅读的个人资料。软件不强制依赖 OCR；图片只是资料正文的配图，用户可以自行决定是否放入正文。

## 2. MVP 范围

### 必须实现

- Windows 桌面 EXE，支持 Windows 10 及以上 64 位系统。
- 新建资料只填写三个核心字段：标题、正文、来源链接。
- 正文使用 Markdown 编辑器；可切换编辑与预览，阅读页默认直接渲染文章，不显示 Markdown front matter。
- 图片支持剪贴板粘贴、文件选择和拖拽导入。
- 图片保存到当前资料独立文件夹的 `images/` 目录，并自动插入正文中的相对路径 Markdown 引用。
- 编辑时可以继续添加、删除和预览正文配图；阅读页只显示正文中实际引用的图片。
- 来源链接在阅读页显示于正文末尾；链接不会被自动塞进正文开头。
- AI 整理为 Markdown：设置页配置一个模型的 API 地址、API Key 和模型，用户可获取模型列表、选择模型、测试模型并保存配置。
- AI 操作使用点击时的表单快照；获取模型列表、测试模型和保存配置互不取消，可同时执行并分别提示结果。
- 不配置 API Key 也可以手动新建、编辑、保存、搜索和管理资料。
- 资料按“一条资料一个文件夹”保存，便于独立备份、迁移和用其他 Markdown 工具打开。
- 支持资料归档、恢复和永久删除。永久删除会同步删除本地资料文件夹、Markdown 文件和图片，资料库中不再显示。
- 用户界面不提供草稿箱；未完成编辑内容只保留在当前编辑会话中。

### 暂不实现

- Telegram 自动登录和历史消息同步。
- 小红书、知乎、抖音等平台的自动发布。
- 云端账号体系和多人协作。
- 依赖数据库才能运行的功能。
- 强制 OCR 或本地 OCR 回退。

## 3. 用户主流程

```text
新建资料
  -> 填写标题、正文、来源链接
  -> 粘贴/选择/拖拽正文配图（可选）
  -> 检查 Markdown 编辑区，必要时点击“AI 整理为 Markdown”
  -> 确认保存到资料库
  -> 首页和资料库以文章卡片/列表展示，点击后直接阅读渲染结果
  -> 点击编辑才进入 Markdown 编辑器
  -> 不常用的资料可归档，需要时恢复；错误资料可永久删除
```

### AI 整理流程

```text
在设置页填写 API 地址和 API Key
  -> 获取模型列表
  -> 下拉选择模型并保存配置
  -> 可随时点击“测试模型”验证当前表单
  -> 在编辑页点击“AI 整理为 Markdown”
  -> 检查模型返回的 Markdown
  -> 用户确认后保存
```

AI 只负责整理格式和表达，不替用户确认事实；请求失败、超时或 Key 错误时，原始正文仍保留。

## 4. 资料文件结构

默认资料库目录可以在设置页修改。每条资料使用独立目录：

```text
资料库/
  articles/
    <文章文件夹>/
      index.md
      images/
        001.png
        002.jpg
```

`index.md` 保存标题、正文和来源链接。正文中的图片使用相对路径，例如 `![说明](images/001.png)`。图片文件只有在正文实际引用时才会出现在阅读页；未引用的图片不会被自动展示。

## 5. 文章字段

| 字段 | 必填 | 用途 |
| --- | --- | --- |
| title | 是 | 资料标题 |
| content | 是 | 用户确认后的 Markdown 正文 |
| source_url | 否 | 来源链接，阅读页显示在正文末尾 |
| created_at | 是 | 创建时间 |
| updated_at | 是 | 最后修改时间 |
| images | 否 | 资料目录中的正文配图 |

系统仍保留对旧资料字段（摘要、来源平台、标签、备注、OCR 源图等）的兼容读取能力，但新建和编辑界面不再要求这些字段，也不会在普通阅读卡片中展示内部 front matter。

资料状态由内部 front matter 的 `status` 记录（正式资料或归档资料）。该字段只用于筛选和生命周期管理，不直接展示给用户。归档不会删除资料文件夹；永久删除才会清理本地全部文件。

## 6. 验收标准

- 不配置 API Key 也能创建资料、保存图片、编辑 Markdown、阅读和搜索。
- 新建资料页面只出现标题、正文、来源链接和配图操作，不出现 OCR 步骤、标签、摘要或备注表单。
- 粘贴、选择或拖拽的图片会保存到当前资料的 `images/` 目录，并在正文中生成相对路径引用。
- 普通查看显示渲染后的整篇文章和正文实际引用的图片；不显示 front matter，也不显示未引用的原始图片。
- 来源链接显示在正文末尾；编辑时修改或删除来源链接会同步保存。
- AI 整理模型可获取列表、下拉选择、单独测试和保存；四项操作互不取消，成功和失败均有清晰提示。
- AI 请求失败时不会覆盖原始正文，用户可以继续手动编辑。
- 资料按独立文件夹保存，重启软件后文字、配图、搜索结果和设置仍然可用。
- 归档资料与正式资料分开显示，恢复后内容不丢失。
- 永久删除后，本地资料文件夹、Markdown、图片和界面记录全部消失，无法从软件恢复。
